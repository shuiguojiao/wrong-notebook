# 学生版界面：手账贴纸

状态：设计说明（2026-11-10）。产品方向已确定；标注“待产品确认”的项目仍需收口。
主力设备为 iPad 横屏 1180×820，其次是 iPad 竖屏、手机和桌面。
实现步骤见 [实现计划](IMPLEMENTATION_PLAN_STUDENT_UI.md)。本文不表示功能已上线。

## 1. 定位与原则

面向初中生的错题本。让小林愿意打开，也能安静地完成复习。
首页先回答“今天做什么、要多久”，再提供录入和管理入口。
手账感来自纸面、便签和改正后的反馈，不靠满屏装饰。

1. 易用。主要任务有明确入口，次要工具收进二级菜单。
2. 有学生审美。方格纸、贴纸、荧光笔和印章形成统一语言。
3. 吸引注意力。只强调今天的任务和已经改正的地方。
4. 复习不分心。作答页进入专注模式，不展示全局导航或奖励弹窗。
5. 内容真实。加载不显示假 0，静态稿中的数字不作为业务默认值。

与 [旧界面方案](UI_REDESIGN.md) 相比，本方案扩大到导航、今天页和收集册。
保留单列题目、统一编辑、出处查看和作答前隐藏原图的基础。
设备优先级改为 iPad 横屏优先；实现仍采用移动优先的响应式 CSS。
题目出处与核对规则继续遵循 [题目完整性设计](QUESTION_INTEGRITY.md)。

## 4. 字体与离线

标题用 ZCOOL KuaiLe，本地自托管，按 OFL 许可分发。
将常用标题字和常用汉字子集化为 woff2，总预算 ≤ 800KB；不下载全量正文中文字体。
声明 `font-display: swap`。缺字回退系统字体，姓名和自定义标题不可显示空白。
字体版权声明与 OFL 许可文件随字体、桌面版、飞牛包和安卓包一起分发。
子集构建需检查上游许可中的保留字体名称要求，记录来源版本与字符集。

S1b 实际字符集为 GB2312 一级 3755 汉字 ∪ `src/lib/i18n/zh.ts` 全部字符 ∪ ASCII 可见字符 ∪ 常用中文标点，共 3905 字符（含一级字库外的“浏、渲、阈”3 字），字体实际映射 3893 字符，woff2 为 451464 字节（约 451.5KB）。源字体未提供的换行、部分符号和 emoji 共 12 字符按后备字体处理。

复现脚本为 `scripts/fonts/subset-title-font.py`，先按脚本顶部说明安装 Python 的 `fonttools` 与 `brotli`，再从仓库根目录执行 `python3 scripts/fonts/subset-title-font.py --source /path/to/ZCOOLKuaiLe-Regular.ttf`。脚本锁定 Version 2.001 及源 SHA256，生成排序去重后的字符集与相邻 JSON 元数据，并在超过 800000 字节时拒绝写入。可用 `python3 -m unittest discover -s tests/publication -p test_title_font.py -v` 独立验证字符集。

字体与原文许可放在 `src/app/fonts/ZCOOLKuaiLe-Subset.woff2`、`ZCOOLKuaiLe-OFL.txt`，生成记录在 `ZCOOLKuaiLe-Subset.json`。分发说明和同一份 OFL 原文沿用现有的 `public/third-party-licenses/zcool-kuaile/` 机制，随 `public/` 进入各服务端安装包与 Docker，字体由 `next/font/local` 输出至 `.next/static/media/`。安卓两种模式另由 Gradle 复制说明与许可至 `assets/licenses/zcool-kuaile/`，客户端版从所连接的服务端加载字体。原许可未声明保留字体名称，子集沿用原名。

本地字体以 `--font-title` 和 `display: swap` 接入，仅在屏幕手账风格下应用于 `h1`、`h2` 与 `.font-title`。简洁风格、管理后台、打印、正文、表单、按钮和 KaTeX 继续使用各自字体。

正文使用 `system-ui, -apple-system, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`。
不从 Google Fonts 或其他远程字体服务加载；设计稿中的外链不进入实现。
已有 Geist 拉丁字体资源如何保留由 S1 核查，学生正文不依赖它，也不新增正文包。
公式沿用 KaTeX 及本地资源，不用标题字体模拟数学排版。

## 5. 风格范围与深色模式

**待产品确认：推荐在用户设置中新增“界面风格：手账 / 简洁”。**
新老账号首次进入均默认手账；用户可主动切回简洁。
两套风格共用组件结构与行为，用根元素 `data-ui="notebook"` / `data-ui="simple"` 切换 CSS 变量。

弹层经 Portal 挂载时仍需继承正确变量；不能只给页面内部包一层。

**待产品确认：首期建议把界面风格作为本浏览器显示偏好，按账号隔离缓存。**

## 6. 奖励与数据口径

只奖励“改正”，不奖励刷题数量；不做排行榜，不以速度比较学生。
“这次做对”是事实记录，不兑换积分。再次做错显示“明天再见”。
连续天数首版按 6.2 的有效复习作答近似计算，不因拍照、录入增加。
举一反三加练完全自愿，不计复习连续天数，不让连续天数成为加练压力。

### 6.1 收集册：从现有数据推算

按用户、学科、标签体系与知识点分组；不混合不同体系的同名标签。
仅纳入至少关联一道错题的知识点。没有题的标签不因“全部掌握”被自动奖励。
单题掌握状态沿用现有阈值与有效作答记录，不把复习轮次结束等同于已掌握。

| 判定优先级 | 条件 | 贴纸与行动 |
| --- | --- | --- |
| 1 | 该知识点下全部错题已掌握 | 已贴上；完整色块、名称 |
| 2 | 未全部掌握，但近期有效作答全对，且至少一次 | 在好转；降饱和、明确文字 |
| 3 | 其他情况，包括近期无有效作答 | 还差 n 题；虚线轮廓、“练这个” |

n 是未掌握题数，不能显示为“再做 n 次就一定掌握”。
“近期”采用近 30 个应用日窗口（含今天）。
排除重复导入、未作答和空结果；撤销、删除、重标标签后重新推算。
“这周新贴纸”用现有记录重放出的掌握变化推算，不能拿题目创建时间冒充获得时间。
若掌握概率变化无法重建到具体日期，只显示“现在已贴上”，不宣称本周获得。

### 6.2 连续天数：完成日，而非活跃日

首版按“当天有复习作答”近似计算：应用日内至少一次有效复习作答（做对或做错）即为完成日。
不含录入、跳过、手动调度、重复导入或举一反三加练；无作答不自动赠章。
按应用时区归日，从今天（无作答则从昨天）向前逐日计算，遇到空缺即止；今天未复习提示“今天复习后继续”。
此简化口径经产品确认，独立于是否已清空今日队列；收工“搞定”章仍要求 S5c 的全科队列核对。
现有活动日统计包含录入，不能直接展示为复习连续天数。
历史完成日重放（依每日任务快照、过去额度与估时的严格口径）暂不实现，不回填或新建表。

收集册、连续天数均不新增数据表，不改 Prisma，不改备份格式。
需要精确“贴纸获得时间”或每日任务历史时另行设计，不能偷偷引入持久状态。

## 11. 作答对照

目的：看到哪里改对了，也能纠正 AI 的判断。
结构：材料摘要 → “你写的 / 参考答案”对照 → 印章与简短提示 → 原图照片卡 → 自评。

## 12. 收工

目的：确认本次已保存，关注改正的地方，安心结束。
结构：完成印章 → 这次做对 / 明天再见 / 彻底掌握三格数字 → 今天的进步 → 新贴纸 → 收工。
“这次做对”取已保存的正确结果；“明天再见”表示仍需巩固，不承诺实际一定次日到期。

“彻底掌握”取本次前后掌握状态变化，异步评估未完成时显示“还在确认”，不借用跳过数。
“今天的进步”只从已有对照与记录生成可核对的说明；新贴纸遵循第 6 节的推算边界。
“收工”回今天；“再来 5 题”为次要入口，有多少可练就列多少，不为了凑数重复题。
加练不增加贴纸积分、不追加当天完成条件。恢复已保存记录后不能重复计数。

## 17. 无障碍与验收

正文、便签黄上的深字、贴纸字与实际背景对比度 ≥ 4.5:1；透明层合成后重新测。
所有操作触控目标 ≥ 44×44px；相邻工具留间距，不能只把图标画成 44px 外观。
状态不只靠颜色：在好转、明天再见、已贴上都有文字；图片和图标有适当名称。
键盘可到全部导航、菜单和抽屉；焦点不被底栏、工具栏或软键盘遮住。
尊重 `prefers-reduced-motion`：关闭印章动画、装饰旋转和切题滑动，不只缩短时长。
材料可缩放，字体回退不裁字，手写有打字替代；不要求精准拖动才能继续。
1180×820、820×1180、390×844 均检查深浅色；桌面补查 1280×900。
检查长题、公式、手写、无原图、AI 判题中、网络失败、空态及软键盘展开。
静态截图通过不等于 iPad Safari 或 Apple Pencil 已验收，须有真机走查记录。
