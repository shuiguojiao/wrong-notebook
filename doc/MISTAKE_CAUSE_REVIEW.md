# 设计方案：错因分类与变式复习

状态：已确认方向，待实现 · 2026-11-24

关联文档：`doc/REVIEW_SCHEDULING.md`（间隔与跳档规则）、`doc/REWARD_SYSTEM.md`（能量豆口径）、`doc/STUDENT_UI.md`（学生端用词与风格）

## 1. 想解决什么

| 问题 | 现状 | 本方案 |
| --- | --- | --- |
| 粗心题和不会的题复习次数一样 | 调度只分记忆型/方法型，错因是一段自由文字 `mistakeAnalysis` | 新增结构化错因 `mistakeCause`，按错因给复习提示，粗心类首次做对就多跳一档 |
| 学生不知道自己常错在哪 | 统计只有掌握率与学科分布 | 统计页显示未掌握题的错因分布，错题列表可按错因筛选 |
| 改错没有留下“教训” | 判题后确认即结束 | 做错时可写一句“下次注意”，下次复习这题时先显示 |
| 后期原题靠记答案做对 | 每轮都复习原题 | 方法型题从第 3 次复习起默认改做 AI 变式题（失败自动回退原题） |

## 2. 错因分类（第一部分）

### 2.1 取值

`ErrorItem.mistakeCause String?`，取值固定：

| 值 | 中文 | 英文 | 含义 |
| --- | --- | --- | --- |
| `concept` | 概念不清 | Concept gap | 定义、性质、公式理解错误或混淆 |
| `method` | 方法不会 | No method | 不知道怎么下手、思路错误、不会做 |
| `reading` | 审题出错 | Misread | 看错、漏看条件，答非所问 |
| `calculation` | 计算粗心 | Careless slip | 方法对，计算、抄写、符号出错 |
| `memory` | 记忆遗漏 | Forgot | 单词、字词、默写、公式记不住 |
| 空 | 未分类 | Unclassified | 旧题、AI 无法判断或文字题未分析 |

不设 `unknown` 值，未知一律存空，前端显示“未分类”。

### 2.2 AI 识别

- `prompts/analyze.ts` 在 `<mistake_analysis>` 之后新增 `<mistake_cause>` 标签，要求只填上表中的一个英文值或留空；规则：
  - 有正式错误解答时，按错误发生的原因选一项；
  - `mistake_status` 为 `not_attempted`（没作答、不会做）时填 `method`；英语、语文的字词默写类填 `memory`；
  - 无法判断时留空。
- 解析在 `response-parser.ts`（及 `base-provider.ts` 中同类解析处）、`schema.ts`；非法值丢弃为空。
- 重新生成解答（reanswer）不改错因，与现有“知识点和错因保持不变”一致。
- 所有由识别结果创建 `ErrorItem` 的入口（单题录入、导入任务、批量导入、Agent/Openclaw 上传、校对页确认）一并写入。

### 2.3 查看与修改

- 详情页错因分析区块顶部显示错因标签（彩色小纸签，沿用学生端风格），点击可改成其他错因或“未分类”。
- 校对页（导入前人工确认）同样可选。
- 修改错因要清空 `reviewSyncedAt`（与改科目、题型一致），因为它影响调度（见 2.5）。

### 2.4 统计与筛选

- 统计页新增“错因分布”卡片：当前筛选范围内未掌握题按错因计数（横向条形，含“未分类”），点击一项跳到错题列表并带 `?cause=<值>`。
- 错题列表支持 `cause` 地址参数与筛选项（`unclassified` 表示空）。

### 2.5 复习中的用法

调度规则（`rebuildReviewTimeline`）唯一改动：

- 错因为 `calculation` 或 `reading` 的题，**第一次做对**按“有把握”处理（跳两档），无论学生选的是哪个。理由：这类题方法已会，主要靠提醒。之后的作答照常。
- 规则必须仍是纯函数：`ReviewItem` 增加可选 `mistakeCause`，`reviewSelect` 补该字段；`doc/REVIEW_SCHEDULING.md` 补一节说明。

作答前的提示（复习卡题干上方一行轻提示，可收起，不剧透答案）：

| 错因 | 提示文字 |
| --- | --- |
| `reading` | 先圈出题目里的关键条件，再动笔。 |
| `calculation` | 做完别急着交，验算一遍。 |
| `concept` | 先想想这题考的是哪个概念。 |
| `method` / `memory` / 空 | 不显示 |

判题后：错因为 `concept` / `method` 且这次做错时，对照区把“看解析 / 看动画讲解”按钮放到最显眼的位置。

### 2.6 “下次注意”

- `ErrorItem.mistakeLesson String?`（最多 80 字）。
- 原题复习或变式复习判为做错，在确认区出现一行可选输入“下次注意什么？”（占位例：“分母不能为 0”），确认保存时写入；留空不覆盖已有内容。
- 下次复习这题时，题干上方先显示“上次你提醒自己：……”（与 2.5 的提示合并为同一行区域，“下次注意”优先）。
- 详情页错因区块里也可查看、修改。

### 2.7 数据与备份

- 一次正式迁移 `mistake_cause_lesson`：两个可空字段，兼容已有数据，不回填。
- 备份格式 21 → 22：导出两个字段；导入旧版本缺省为空，非法 `mistakeCause` 值丢弃。
- Excel/Word 导出不新增列（本期不做）。
- Agent API 读写错题时一并返回、可写 `mistakeCause`（按现有字段校验方式）。

## 3. 变式复习（第二部分）

### 3.1 何时用变式题

复习队列中的一道题，同时满足以下条件时默认出变式题：

1. 调度类型为方法型（`reviewKind === 'method'`）；
2. 当前 `reviewStage >= 2`（已完成至少两轮复习，即第 3 次及以后）；
3. 题目有参考答案；
4. 用户已同意 AI 数据授权、AI 可用、未超日/月额度；
5. 用户设置“后期复习用变式题”开启（默认开启，位于复习设置，按用户保存并随备份导出）。

勇者题入口不变，仍做原题。

### 3.2 流程

- 复习卡标题旁显示“变式题”小纸签，题干下方可折叠“看原题”（只读，不含答案）。
- 变式题复用举一反三的生成与判题接口（同知识点、同难度档：按原题星级 ≤2 → easy，3 → medium，≥4 → hard）。
- 会话开始后，对队列中接下来最多 2 道符合条件的题**预生成**，减少等待；生成中显示与现有一致的加载态。
- 生成失败、超时（20 秒）或额度不足时，自动改做原题，并在卡片上轻提示“这次先做原题”；不报错、不打断会话。
- 卡片“更多”里可手动“换成原题”。
- 作答结果写一条 `PracticeRecord`（`errorItemId` 指向原题），与原题复习同样参与调度重放、掌握度评估和复习时长统计。

### 3.3 记录来源与奖励口径

- 新增 `source = 'variant_review'`。凡按 `source` 区分的地方都要核对一遍（复习统计、做题记录列表、能量豆规则、掌握度评估输入、导入导出、历史视图），口径：
  - 调度、掌握度、今日完成进度：等同原题复习；
  - 能量豆：按“复习一道题 1 颗 + 改正 2 颗”计，**不**计入举一反三的每日 5 道上限；
  - 做题记录：显示为“变式复习”，展示变式题题干、作答与判题依据。
- 备份：`source` 为字符串，旧版导入无影响；新值随记录导出导入。

### 3.4 不做

- 不在后台批量预生成全部变式题（成本不可控）。
- 不改记忆型题的复习方式。
- 不做“考前冲刺”。
