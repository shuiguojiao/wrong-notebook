# 做题记录：按天回看做过的题

状态：已确认（2026-11-10），实现中。主力设备为 iPad 横屏，同时兼容手机。用词与风格遵循 `doc/STUDENT_UI.md`。

## 1. 问题

作答数据都已保存（时间、对错、用时、把握程度、手写或拍照答案、AI 转写、判题依据），但只有两种看法：

| 现有入口 | 能看到 | 看不到 |
| --- | --- | --- |
| 错题详情 →“复习”摘要弹窗 | 这一道题的每次作答 | 某一天做了哪些题 |
| 我的 → 学习统计 → 练习统计 | 26 周学习日历、正确率趋势 | 具体是哪些题；日历格子只有悬停提示，iPad 上点不开 |
| 复习结束的收工小结 | 这一组的对错清单 | 离开页面后找不回来 |

学生想回答的是“我今天（昨天、上周三）做了什么，哪些错了，当时是怎么写的”；家长想回答的是“这周有没有做，做得怎么样”。两者用同一个页面。

## 2. 设计原则

1. **按天，不按题**：时间是这个页面唯一的主轴，题目是天下面的内容。
2. **先看结论，再看过程**：每天一行小结，展开才是逐题；逐题先看对错，点开才是当时的作答。
3. **只读**：这里是回看，不是改成绩的地方。更正结果仍在原题详情或试卷页进行。
4. **不比较、不排名**：不显示“比昨天少”“低于平均”之类的话；做错的题用橙色“差一点”章，不用红叉（`STUDENT_UI.md` 第 6 节）。

## 3. 入口

| 位置 | 形式 | 落点 |
| --- | --- | --- |
| “我的”学习区第一行 | “做题记录” | 今天 |
| 今天页的连续天数印章 | 点击 | 今天 |
| 收工小结底部 | “看看今天的记录”文字按钮 | 今天 |
| 学习统计的学习日历 | 格子可点（最小点击区 28px，选中后下方显示当天小结与“查看这天”按钮） | 所选日期 |
| 错题详情“复习”摘要弹窗里的每条记录 | 日期可点 | 那一天，并定位到该条 |

路由 `/history`，参数 `?date=YYYY-MM-DD&record=<id>`，可直达、可刷新。不进入四个主导航，避免喧宾夺主。

## 4. 页面

### 4.1 iPad 横屏（≥1024px）：左列表，右详情

```
┌────┬──────────────────────────────┬───────────────────────────────┐
│侧栏│ 做题记录        [数学][英语] ☐只看差一点 │  第 3 题 · 复习 · 19:42 · 用时 1分20秒 │
│    │ ‹ 一  二  三  四  五  六  日 ›        │  ┌───────────────────────────┐ │
│    │   ●  ●  ○  ●  ◉  ·  ·   回到今天   │  │ 题目（公式正常渲染，配图可放大）│ │
│    ├──────────────────────────────┤  └───────────────────────────┘ │
│    │ 11月10日 周二                       │  我当时写的                      │
│    │ 做了 14 题 · 对 11 · 复习用时 26 分钟    │  ┌───────────────────────────┐ │
│    │ ─ 复习 · 12 题 ─────────────── │  │ 手写/照片（点开放大）或键盘文字 │ │
│    │ (对)   数学  已知 x²−3x+2=0 …  19:40 │  └───────────────────────────┘ │
│    │ (差一点) 数学  如图，△ABC 中 … ✎ 19:42 │  参考答案（默认折叠，点开）          │
│    │ (对)   英语  She ___ to school… 19:45│  为什么这样判：……                  │
│    │ ─ 再来一道类似的 · 2 题 ───────── │                                 │
│    │ ─ 试卷《周末小测》· 对 7/10 ▸ ───── │  [打开原题]                       │
│    │ 11月9日 周一 …                      │                                 │
└────┴──────────────────────────────┴───────────────────────────────┘
```

- **周条**：一周七天，每天一个 44px 的圆点。空心是没做，实心是做了，带勾是当天全对；选中的那天加粗描边。左右箭头或横向滑动换周，“回到今天”一键回来。点周条标题展开成月历，用来跳到更早的日期。
- **天标题**：日期、星期、“做了 n 题 · 对 m”，有复习用时就加“复习用时 x 分钟”（只有复习记录有用时，其他来源不估算）。标题吸顶，滚动时始终知道在看哪天。
- **分组**：一天之内按活动分组，顺序为复习、再来一道类似的、试卷、手动录入。试卷默认折叠成一行“《标题》· 对 7/10”，点开看各题，另有“打开试卷”。
- **题目行**（高度不低于 56px）：结果章、学科贴纸、一行题干预览（复用 `ReviewQuestionPreview`，公式要渲染）、有手写或照片时显示笔形图标、时间。同一题当天做了多次就按时间出现多行，不合并。
- **右侧详情**：选中一行后显示。内容依次是题目、“我当时写的”、参考答案（默认折叠，避免一眼扫到）、判题依据、把握程度（“会了”/“还不太熟”）。按钮只有“打开原题”。举一反三和试卷新题显示的是当时那道新题，不是原题。
- 未选中时右侧显示当天小结卡：各学科题数与对错，文字描述，不放图表。

### 4.2 iPad 竖屏与手机（<1024px）：单栏

周条与列表同上，单栏排列。点题目行从底部升起详情面板（手机占 90% 高度，iPad 竖屏占 70%），下拉或点“关闭”收起，列表保持原滚动位置。筛选收进标题右侧的一个“筛选”按钮。

### 4.3 筛选

- 学科：贴纸样式的单选，“全部”加各学科，默认全部。
- “只看差一点”：只留做错的记录。打开后，没有错题的日子整天隐藏，周条圆点不变。
- 不做搜索。要找某道题去错题本。

### 4.4 加载与空状态

- 首次加载最近 7 天，滚到底自动再加载 7 天；中间没有记录的日子直接跳过，到最早一条记录为止，之后显示“更早没有记录了”。
- 选中的那天没有记录：显示“这天没有做题”，不配插画，不催促。
- 从未做过题：显示“还没有做题记录”和“去今天看看”按钮。
- 加载中用骨架行，不显示 0（避免先出现“做了 0 题”再跳变）。失败时该段显示“没加载出来，再试一次”。

## 5. 数据口径

- 来源：`PracticeRecord`，按 `createdAt` 归到应用时区的日期（`getAppTimeZone`）。试卷记录的时间是录入时选的考试日期，因此会出现在考试那天。
- 包含：`review`（复习）、`practice`（再来一道类似的）、`exam`（试卷）、`manual`（手动录入）。
- 不包含：`duplicate_import`、`result` 为空的记录。`not_attempted` 只可能来自试卷，显示为灰色“没做”，不计入“做了 n 题”。
- “对 m”按 `result = correct` 计；旧记录 `result` 为空但 `isCorrect` 有值的，沿用练习统计的回退规则。
- 这里的“做了 n 题”是作答次数，与连续天数（只算复习）是两个口径，页面上不混用同一个词。

## 6. 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/practice/history?before=YYYY-MM-DD&days=7&subjectId=&result=wrong` | 返回 `days[]`：每天的小结（总数、对、错、没做、复习用时）与记录列表。记录字段：id、来源、结果、时间、用时、把握程度、学科、题干预览、是否有作答图片、原题 id、试卷 id 与题号 |
| `GET /api/practice/history/calendar?from=&to=` | 周条与月历用：区间内每天的总数与对的数量，区间最长 62 天 |
| `GET /api/practice/record/:id` | 详情：题目、参考答案、解析、作答文字、作答图片地址、AI 转写、判题依据。图片沿用 `/api/error-items/:id/image?record=&field=answer` |

都用 `withUser`，只查当前用户；参数用 zod 校验。`@@index([userId, createdAt])` 已存在，够用。

**不改 Prisma，不改备份格式**（仍为 17）。

## 9. 已确认

1. 页面叫“做题记录”。
2. 记录页只读，不提供删除。
3. 试卷拍照交卷上线后（`doc/EXAM_ANSWERING.md`），试卷行直接打开那次的批改结果页。

能量豆：每天标题行末尾仅在该日期选中时读取 `/api/rewards/ledger?day=` 并显示当天所得，零颗显示“—”。关闭奖励时隐藏，不对历史列表逐天请求。
