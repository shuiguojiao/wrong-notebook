# 每日复习提醒

[English](REVIEW_REMINDERS.en.md)

在「设置 → 通用 → 复习提醒」选择一个渠道、填写凭据和每天的 `HH:mm` 时间，然后保存并发送测试消息。默认关闭。开启后，今日额度内今天要复习的数量、科目和预计分钟数会发送到你选择的第三方推送服务；不发送题目图片、正文或答案。测试消息不需要有到期题，一分钟内最多一次；先保存再测试。留空凭据输入框会保留原值，切换渠道需要重新填写。页面只显示凭据末四位（不超过四位时全部隐藏）。

## 获取渠道凭据

| 渠道 | 获取方式 |
| --- | --- |
| Bark（iOS） | 安装 [Bark](https://bark.day.app/)，复制首页设备 key，或完整 `https://api.day.app/<key>` 地址。 |
| Server酱 | 登录 [Server酱](https://sct.ftqq.com/)，按[指南](https://sct.ftqq.com/docs/getting-started/sendkey/)绑定接收方式并复制 SendKey。 |
| PushPlus | 登录 [PushPlus](https://www.pushplus.plus/)，绑定接收端，复制用户 token。 |
| 企业微信群机器人 | 在企业微信群添加群机器人，复制 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...`。 |
| 飞书群机器人 | 在群设置中添加[自定义机器人](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)，复制 `https://open.feishu.cn/open-apis/bot/v2/hook/...`。 |
| 钉钉群机器人 | 在群的智能群助手中添加[自定义机器人](https://open.dingtalk.com/document/robots/custom-robot-access)，复制 `https://oapi.dingtalk.com/robot/send?access_token=...`。若设置关键词，请包含「错题本复习提醒」；不支持额外的动态加签密钥。 |
| 自定义 webhook | 管理员开启「允许自定义提醒地址」后，填入接受 POST JSON `{title, body, url?}` 的 HTTPS 地址。没有站点配置时省略 `url`。自建 Bark 可通过兼容的转发接口接收该 JSON；预设 Bark 仅支持官方主机。 |

机器人必须按所用平台的安全要求配置；飞书额外签名校验未接入，可使用适合部署环境的关键词/IP 白名单。额度、服务可用性、平台权限及设备通知设置也会影响接收。「推送服务已接受」只证明服务端接口成功，不证明手机收到。不同平台可能把正文中的 URL 显示为普通文本。

## 管理员与部署

- 保持 Next.js Node 服务持续运行。每分钟检查一次，按 `getAppTimeZone()` 的应用时区判断到点；当天启动较晚时会补检查，停服期间不能发送，隔日不补历史提醒。桌面版需运行，安卓单机版需保持服务存活；无常驻服务的 Serverless 部署不保证定时执行。
- 配置 `.env` 的 `NEXTAUTH_URL=https://你的站点`，消息会包含 `/review` 链接，打开后仍需登录；没有有效配置时省略链接，设置页提示管理员。手机应能访问该站点。
- `REVIEW_REMINDERS_ENABLED=false` 全局关闭自动提醒和测试消息（修改环境变量后重启）。默认允许使用功能，但每个用户默认关闭。
- 「设置 → 通用」的管理员系统配置中可开启「允许自定义提醒地址」和「允许自定义提醒访问内网地址」，对应 `config/app-config.json` 的 `allowCustomReminders` / `allowPrivateReminders`，两者默认 `false`，随页面全局配置保存按钮保存。允许内网仅对自定义渠道生效，仍必须使用 HTTPS 和受信任证书。
- 预设渠道固定官方主机与路径，仅允许 HTTPS 默认端口；不跟随重定向。自定义渠道发送前检查所有 DNS 解析结果，拒绝回环、私网、链路本地及特殊地址，连接固定到已检查地址以防 DNS 重绑定。管理员显式允许内网后才放开地址检查。所有渠道总超时 10 秒（含 DNS），不使用系统代理。不要对不可信用户开放内网开关。

## 去重、重试与备份

提醒与首页及 `/api/review/due` 共用分钟额度队列：扣除今天已复习记录的估计用时，按复习轮次、逾期比例等优先级及各科轮流出题，只统计额度内题目并按错题本的科目名称汇总，未归属科目的记为「未分类」。今日队列为空（含额度已用完）时标记当天已检查并跳过。停用账户不发送。

数据库记录应用时区的日历日期、尝试数和完成标记。自动提醒每天成功后不再发送，保存设置、修改时间、重启以及个人备份导入均不清除当天账本。失败后至少等待 30 分钟再重试，最多重试两次，共三次尝试；冷却期间无法发送测试消息。一个用户失败不会阻塞其他用户。使用数据库比较并交换及租约防止并发调度重复发送。

第三方接口没有通用幂等键：网络超时后重试仍可能造成第三方重复接受，不能保证端到端恰好一次。为避免进程在发送成功后崩溃而盲目重发，发送前先写当天完成标记；若进程在此后崩溃，当天可能漏发。部署时请避免在发送期间停机。恢复整站的旧数据库会连同旧账本回滚，恢复当天应先关闭总开关并核对发送情况；修改全局时区也可能改变“今天”的日期边界。

个人 JSON 备份第 **13** 版包含提醒开关、渠道、**完整明文凭据**、时间与最近发送结果；请像密码一样保管，不要公开或发给他人。个人备份不重置服务器的当天账本；旧版本没有提醒字段时关闭提醒。导入后发送前仍会检查当前管理员策略、主机与内网限制。整站 SQLite 快照含所有用户的提醒配置、凭据和账本，恢复时需单独保护文件权限。

实现入口：`src/lib/reminders/`、`src/lib/review-due.ts`、`src/instrumentation.ts`。只记录渠道和固定结果，不记录凭据、第三方原始错误或响应；Prisma 使用最小错误格式，避免在调用参数中输出凭据。

提醒按持久化 nextReviewAt 筛选并应用每日额度；旧题在读取前自动重放初始化。可在「设置 → 通用 → 复习」调整每天分钟数（默认 30，10–180、步长 5）。消息附「约 X 分钟」，积压题与额外一组不计入自动提醒；提醒不展示积压数量。
