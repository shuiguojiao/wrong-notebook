# Practice and Exams

## Similar-question practice

Open similar-question practice from a question's detail page and choose a difficulty; the AI generates a variant testing the same knowledge points. Generated questions are fill-in-the-blank or free-response, and the question text should not carry a question number, score or multiple-choice options.

Opening `/practice` without a question ID explains how to enter from a question’s detail page using **Try a similar question**, with **Go to notebooks** (`/notebooks`) and **Back to today** (`/`) buttons. Errors also retain in-page exits.

Answer on your own first, then view the answer and analysis and record whether you got it right. Records are linked to the original question for reviewing practice history and evaluating mastery.

Answers are checked when you submit. If your text-only answer matches the reference answer (ignoring spaces, formula delimiters and prefixes like "The answer is"; for multiple choice only the option letters are compared), it is marked correct right away. Otherwise the AI compares it with the reference answer and analysis and gives a one-line reason. Equivalent forms (such as `1/2` and `0.5`) count as correct; giving only some of several answers counts as wrong. If the AI check fails, you choose the result yourself. The check is only a suggestion and can be changed before saving.

Each question keeps the most recently generated variant and its solution. Reopening practice shows that question and when it was generated without calling the AI again; click "Regenerate" for a new one, which replaces the saved variant.

Saving a practice result also saves your answer, working notes and the automatic grading reason in the original question’s expandable answer history. Changing the suggested result does not overwrite the original grading reason. Grading checks the displayed question version; if another tab has regenerated it, automatic grading stops and your work is preserved. You can check against the answer on the current page and confirm the result manually, or reload the new question.

### Photo answers

Original review and similar-question practice support Keyboard / Handwriting / Photo. Non-touch desktop browsers label the last option Upload a photo. Take a photo opens the system rear camera, while Choose from library selects an existing image. Rotate right in the crop dialog and keep only your working. Images are processed locally for HEIC decoding and orientation, then the crop is resized to a longest edge of 2000px and JPEG-compressed starting at quality 0.85 to fit 1.5MB per photo. Images that cannot be opened prompt you to choose another.

Keep up to 3 photos, with retake, rotate right 90°, delete and add controls. Any text, ink or photo enables submission, and dots mark tabs with content. Grading sends handwriting first, then photos, up to 4 images in total. Photos stay in memory for the current answer and survive submission and Undo, keep writing. Changing questions clears them. When AI cannot read an image, Hard to read — retake returns to the Photo tab with all answer content preserved, beyond the three-second undo window and without saving an answer record. Self-assessment confirmation saves a vertically composed display image. Comparison and answer-history images open at full size when clicked.

## iPad and Apple Pencil handwriting

Wide screens allocate question/answer columns at 2:3, with independent scrolling for long questions, compact tools and a canvas sized to the remaining viewport. Logical width stays 1000; height follows the container ratio without a hard cap, avoiding dead areas at extreme ratios. Backgrounds cover the paper and resizing never rewrites stroke coordinates. Ink outside a shorter view is retained and included in export.

Original reviews and similar-question practice both offer Keyboard / Handwriting / Photo. Typed text is optional. Text, strokes or photos enable submission and are graded together. Switching preserves all inputs. On mobile the question is above the canvas; wide screens (1024px and up) place them side by side. Vector drafts remain in the current page across rotation and window resizing. Refreshing, leaving the question or successfully generating a new one clears unsaved drafts.

- Use black, blue or red ink in three widths. Pencil uses actual pressure; mouse and touch use simulated pressure.
- The eraser removes whole strokes. Undo/redo keeps the last 50 operations, including clear. Choose blank, grid or ruled paper.
- Pencil only turns on after the first pen input, and the browser remembers that a pen was detected. Fingers scroll when enabled and draw on the canvas when disabled. Pen input takes over an unfinished touch stroke and rejects palm touches. Scroll using the toolbar or outside the canvas as well.
- Submission crops the strokes with padding onto white, choosing the smaller PNG/JPEG. The longest edge is at most 1600px and the image at most 1.5MB, reducing resolution and quality if necessary. Paper guides are excluded. Export failure keeps the draft for retry; submitted strokes are read-only.

Answers with handwriting always use AI grading, asking for transcription, step checking and specific errors; matching typed text cannot bypass image grading. Configure a model that supports images. OpenAI/Azure, Gemini and Anthropic reuse their existing multimodal transports. Transcription is shown separately and never replaces typed text. Illegible content should be marked rather than guessed; you still confirm correct/incorrect. If AI grading fails, the answer remains available for manual confirmation.

Confirmation saves the composed answer image (`answerImageUrl`), transcription (`recognizedAnswer`), typed text and grading reason in expandable answer history. Images use authenticated local storage. Full backups carry their contents, and older backups restore missing fields as null. `POST /api/practice/grade` accepts an optional `answerImages` data URL array (1–4 images) and the legacy `answerImage` field. Grading requires text or images. `POST /api/practice/record` continues accepting an optional single `answerImage` and `recognizedAnswer`.

Grading accepts up to 4 ordered answer images. Legacy `answerImage` and new `answerImages` are merged and deduplicated with the legacy image first, with PNG/JPEG/WebP and a 1.5MB limit per image. Unreadable images return `correct: null` and `unreadable: true`, keeping the reason for manual self-assessment. Grading uses the separate originals. Comparison and confirmed records use one locally composed vertical image, initially 1000px wide with a white background and 24px light-gray separators, progressively JPEG-compressed and proportionally resized when needed to fit 1.5MB. The handwriting canvas exports one image, which can be submitted with up to three photos.

Submitting for grading sends handwriting to the configured AI provider under existing AI data consent. See the [privacy notice](../../PRIVACY.en.md).

On iPad (≥768px), the submit button sits at the top right beside the keyboard/handwriting/photo switch and is at least 44px high. Phones retain a bottom submit bar, with ink tools above the paper and 48px of content clearance. Touch submission is ignored while Pencil is down and for 800ms after lifting it. Pen and keyboard submission remain available. Submission opens comparison immediately. For three seconds, “Undo, keep writing” restores text, ink and photos, aborts grading and discards late results. Original-review timing resumes from its paused total. Answer records are saved only after self-assessment confirmation. The existing post-save undo notice remains separate. Native non-passive stylus touch handlers prevent accidental scrolling while retaining finger-scroll settings. Missing pointer-up events, subsequent pen-down events and backgrounding preserve collected strokes. Newly collected pen pressure maps to 0.35–1 with thinning 0.45. Simulated pressure for other pointers retains its behavior, and existing point data needs no migration.

## Mastery

Mastery probability is estimated from the actual answer history linked to the original question, including similar-question practice, exam answers and repeated imports.

- AI evaluation is used first; if the AI call fails, a rule-based estimate is used and the source is recorded.
- A question's status is decided automatically by its answer records and mastery probability, not marked manually:
  - **Still learning** combines internal `new` (no answered practice records) and `reviewing` (answered records below the threshold or not yet evaluated).
  - **Mastered** has answered practice records and a probability at or above the threshold; the internal status remains `mastered`.
- The mastered threshold defaults to 50% and each user can change it in **Settings → General** (a whole number from 1% to 100%). Status filters, statistics and the mastery scope of random exam papers use the new threshold immediately.
- Notebooks and random exam papers use Still learning / Mastered. Lists accept `mastery=unmastered`; legacy `new` and `reviewing` parameters retain exact filtering, and printing shares the list filters.
- Without usable answer records, the mastery probability is empty.
- Evaluation runs in the background, so after recording results you may need to wait or refresh to see the update.

Mastery probability helps plan reviews. It does not guarantee the student understands the question and is not an exam score.

## Daily review

Today and the retained `/review` route share today’s review area, showing due questions within the daily minute budget.

- English and Chinese fill-in-the-blank questions use a memory schedule; other subjects and types use a method schedule. The current type list cannot identify every dictation or recitation question, so only Chinese fill-in-the-blank is treated as memory.
- A confident correct answer advances two rounds, an unsure correct answer one; a wrong answer goes back two rounds, and two consecutive wrong answers restart from the first round. Dates use the least-loaded day in a small window, with estimated minutes as load and a question hash to break ties.
- Early correct answers anchor the new interval to the original due date; other intervals count from the most recent answer, whether from original reviews, similar-question practice, manual entry, exams or duplicate imports; "not attempted" records do not change the schedule.
- Completing all review rounds removes the question from daily review; a later wrong answer continues from the last round. Dates follow the application time zone, and earlier rounds, overdue ratios, due dates and IDs determine priority before subject rotation.
- Today (`/`) starts with the application-time-zone date, a greeting and estimated review minutes, then subject counts and estimates. Subject rows show read-only reviewed/total counts; the total combines today’s reviewed questions and the remaining budget queue. The question detail’s **Review schedule** shows **Round N of M** and the next date, or **Review completed**. **Mark review complete** removes it from daily review; **Restart review** starts from the first round tomorrow. These actions add no answer record and do not change AI mastery. Later answers and deletions preserve the latest manual adjustment; backdated records before that adjustment do not override it.

Schedules are replayed from answer history and the latest manual adjustment, with persisted dates for efficient queries. Old questions initialize by user and baseline due date on first read, with load-aware selection for the final answer step, so deployment needs only the formal database migration. Review completion and mastery are independent.

Sessions use `format=ids`; add `mode=extra` for an extra group. There is no limit parameter. `DELETE /api/review/undo?recordId=…` accepts only the current user’s latest answer record, from review and no older than one minute, with an original question still owned by that user. The server grace period accommodates request delays. Validation, deletion and schedule recalculation run in one transaction, followed by mastery reevaluation. The existing general-purpose record deletion endpoint keeps its original semantics.

## Generate an exam paper

1. Open the exam entry and choose the scope: notebooks, knowledge points, question types, mastery and so on, plus the mode (Similar Questions / Original). Question types are optional (leave empty for no restriction); you can also select one or more types to only pick questions of those types, including "Not set" (questions without a question type).
2. The system picks questions from that scope (by default **Least practiced first**: questions with fewer practice records come first; for ties, questions that have never appeared in an existing exam paper come first, then random; **Fully random** is also available).
3. **Similar Questions** (default): the AI generates a variant for each question. Check the progress in background tasks; when it finishes, open the paper and check the questions, figures and answers. You can choose the difficulty (Easy / Medium / Hard / Challenge).
4. **Original**: uses the original question text, answer, analysis and figure directly. No AI is called and no AI quota is consumed; the paper is ready to print immediately. No difficulty selection needed.
5. Print or export it, then choose **Enter results myself** to open the grading results page. Select **Correct / Almost there / Not attempted** for each question and an exam date (today by default; past dates allowed, future dates blocked). Once all questions are checked, **Confirm and save** writes the original-question history.

When creating an exam, turn on **Generate A/B papers simultaneously**. The system picks up to 2× the question count of non-overlapping questions under the same conditions and splits them into two parallel papers, balanced by question type and difficulty: Paper A and Paper B have no overlapping questions, with similar type distributions and difficulty levels—suitable for class quizzes or comparison practice. Titles automatically get the suffixes "(Paper A)" and "(Paper B)". In Similar Questions mode, each paper generates separately and consumes its own AI quota. When there are not enough source questions, Paper B is still created as long as it gets at least one question (it may have fewer questions than Paper A) and a warning is shown; if Paper B would get zero questions, only Paper A is created.

Original-mode papers do not show the "Regenerate question" button (the original question cannot be replaced), but "Regenerate solution" is still available; recorded results store no difficulty.

In the exam list a paper shows Generating, then Generated (or Partly failed / Failed), and Completed once results have been entered.

Exam papers keep the source question IDs so you can go back to the originals. Results can be correct, wrong or not attempted; the same question can keep several results, all linked to the original question's review history.

Each question can have its own score (0–1000, up to one decimal place such as 2.5), or you can apply a uniform score to every question at once; leaving it empty means no score is set. The paper header shows the total score (only questions with a score are summed, with a note of how many questions have no score). In the printout the question number is followed by "(N pts)", and the full score line sits under the title; papers without any score print exactly as before. Scores are included in backup export and import.

The exam detail page has a "Group by question type" switch: when on, questions are grouped into sections such as Single Choice and Fill in the Blank (in the default question-type order), each section header shows the question count and the score subtotal ("N question(s), X pts in total", noting how many questions have no score when partially set), and question numbers run continuously across sections. Printing and HTML export use the same sections, with bold section titles bordered above and below, suitable for black-and-white printing. The question type is snapshotted from each source question when the paper is created; for older papers without a snapshot, the current type of the linked source question is used, and questions whose source was deleted or whose type is unknown fall into "Other". The switch and the type snapshots are included in backup export and import (backup version 11).

## Statistics

Mistake statistics show total questions, still-learning count, mastered count, mastery rate, subject distribution and a trend chart. Practice statistics separately show practice count, accuracy, active days, and distribution by difficulty and subject. Both tabs support filtering by time range (last 7 days / 30 days / 6 months / all time) and subject. When a subject is selected, clicking the Still learning / Mastered cards jumps directly to the corresponding filtered error list of that notebook (the URL carries a `?mastery=` parameter to preset the filter). The trend chart shows daily or monthly bars depending on the selected granularity, with two series: "Added" counts mistakes created within each bucket, and "Newly Mastered" counts mastered mistakes whose most recent mastery evaluation falls within each bucket (an approximation using the latest evaluation time as the mastery time; such mistakes may have been created before the range, so they are not restricted by the creation-time filter). Comparing the two series reveals whether your mistake notebook is shrinking or accumulating. Below the subject distribution and trend chart, the mistake statistics tab also shows a "Mistake Cause" card: the top half is a donut chart of attempt status (not attempted / wrong attempt / unknown) with counts and percentages, and the bottom half is a horizontal bar list of error types (name + count + progress bar). Error type is free text; only the top 7 by count are shown and the rest are merged into "Other". When no error types have been filled in yet, a hint is shown instead. The stats respect the current time-range and subject filters. Next to the Mistake Cause card, the mistake statistics tab also shows a "Difficulty Distribution" card: for each difficulty level (1–5 stars), the total number of mistakes and the mastered count are displayed as a stacked horizontal bar, with unrated mistakes listed separately. When there are no rated mistakes at all, this card is hidden. The mistake statistics tab shows a Collection summary and entry from the same progress service, using all questions and the subject filter independently of the statistics date range. The legacy `/api/stats/weak-tags` endpoint remains compatible. The practice stats tab also includes a "Learning Calendar" heatmap at the top: a GitHub-style grid showing daily learning activity (recorded mistakes + practice count) for the last 26 weeks, along with current streak, longest streak and total active days. Recording mistakes counts as activity, so the heatmap is visible even when there are no practice records yet. At the bottom of the practice stats tab there is also a "Repeated Mistakes" ranking: the top 10 questions answered wrong 2 or more times within the selected range (including similar-question practice, exam answers, manual entry and duplicate-import wrong records). Each row shows a question preview, subject, wrong count, the most recent wrong date and the review status; clicking a row opens the question details, highlighting questions worth revisiting. When there are none, a short hint is shown instead.

Knowledge points also live in the stats center: the **Knowledge Points** tab shows a tag system switcher at the top (visible once another tag system is imported), a usage frequency Top 20 card below (counting identically named points in different tag systems or subjects separately), and the standard knowledge points for each stage and subject with custom tag management at the bottom, all shown and added per the selected system. Old `/tags` links redirect here.

Dates and statistics boundaries use the [app time zone](Settings-and-Users-en). Changing the time zone affects daily and monthly grouping but does not shift the times stored in the database.

### Collection and review streaks

Collection shows all related knowledge-point stickers, grouped by user, subject and tag system, with stable ordering and state filters. A sticker is Earned when all its questions are mastered; otherwise it is Improving when there is at least one valid answer and all valid answers in the last 30 application days are correct. Other stickers show the number of unmastered questions and link to that knowledge point’s unmastered list within its tag system. Tags without questions are excluded; undo, deletion and retagging recalculate the result. Today shows the review streak and verifiable New stickers this week (weeks start Monday). This release confirms first mastery only when a knowledge point’s questions each have a single valid answer evaluated on that same application day; uncertain dates are omitted from weekly rewards while earned stickers remain in Collection. The first release approximates a completed day as one with at least one valid original-review answer in the application time zone. Imports, skips, manual scheduling, duplicate imports and similar-question practice do not count. Before today’s first review, the streak ends yesterday and says Review today to keep going. This is separate from active days in the statistics calendar. All progress is derived without new tables or backup-format changes.

## Exam attempt APIs (backup version 18)

The server supports starting or resuming an attempt, saving typed answers and images, flags, cumulative duration, submission, manual results, confirmation and abandonment. Each paper has one unfinished attempt, reused across input kinds. Attempt details hide reference answers and explanations until submission. Exact local text matches are prefilled as correct, empty answers as not attempted, and other answered questions with reference answers are graded in the background for human confirmation.

Confirmation writes original-question history and synchronizes review scheduling. Reconfirmation replaces records from the same attempt. Attempts and history share content-addressed image references; files can be deleted only after the last reference is removed. The **Enter results myself** action opens the shared grading results page, resuming an unfinished attempt when one exists. **Attempts** lists each attempt’s number, date, method, correct count and status. Question cards retain legacy manual records and link newer records to their attempt. Manual attempts stay in question-number order until first saved. Other attempts are grouped and ordered on load or after saving, with card positions fixed during editing. The results header and Done stamp use localized short dates. Counts update immediately; scores appear only when every question has points. The remaining-question count locates the first unchecked question. Saving makes the page read-only with a **Done** stamp and correction links for wrong answers. **Edit results** allows reconfirmation, replacing the same attempt’s records. Unconfirmed attempts can be discarded after confirmation; saved attempts cannot be deleted. Answer images, text, AI transcriptions and reasons appear only when available. The legacy `POST /api/exams/:id/results` endpoint remains compatible. Online answering and background grading are described below; whole-page photo submission is covered below.

## Online exams and background grading

Select **Start answering** on an exam, or **Continue answering (a/b answered)** to resume. Each exam allows one unfinished attempt. Finish or discard an existing attempt in another mode first.

Answering and grading hide global navigation. At widths of at least 1024px, questions and answers appear side by side; narrower screens stack them. Question buttons are at least 44px: filled means answered, outlined means unanswered, and a flag means come back later. Narrow screens open a number panel from the progress button. Left/right arrow keys switch questions when focus is outside an input. Reference answers, explanations and source links stay hidden before submission.

Keyboard, handwriting and photo input reuse the review components, including more paper, focused writing and Pencil settings. Text, editable strokes and up to three photos are stored per attempt and question in this device's IndexedDB, survive switching and refresh, and are excluded from personal backups. Changes save after two seconds, on question changes and when the page becomes hidden. Failures retry with exponential backoff and upload again on reconnect. The server stores text, a composed display image and up to four grading originals. On another device, the server image is read-only with **Clear and rewrite**. The hideable timer counts foreground answering time only and uploads accumulated duration.

Handing in waits for saves, then shows answered, unanswered and flagged questions with links back to them. Touch submission is ignored during pen use and for 800ms afterwards. Submission cannot be undone. Deterministic text matches are marked correct locally; remaining answered questions with reference answers are graded in the background, up to three at once. A paper consumes one daily AI action, with actual tokens recorded. If quota is exhausted, results open for self-checking. Failures and interrupted tasks are not automatically retried. Each question can be regraded twice without an extra daily action; tokens are still recorded. Today shows grading and unconfirmed-result reminders.

Results retain the student's image, text, collapsible transcription and grading reason. AI results are suggestions. Only **Confirm and save** updates learning history and review scheduling. Confirmation clears grading originals and recycles unreferenced files, retaining the display image. Backup version 18 includes grading originals and retry counts and supports version 17 and earlier. For whole-page photo submission, see Submit photos.

On wide screens, the question legend sits beside the question numbers; on smaller screens it appears only in the expanded number panel. Typed answers scroll within the available viewport above the bottom bar. Results show seconds only for attempts under a minute, and ungraded answers show one reason alongside an available regrade action.

### Submit photos

After finishing on paper, choose “Submit photos” on the exam page. Upload one image per page, up to 8, with reorder, rotate, retake and delete controls. Pages upload individually, then background location and grading use one action for the whole attempt. Unreadable or mismatched pages return for retaking, and only changed pages are located again. Red corrections covering at least half the original questions prefill results, while AI conflicts require attention. For missing answers, choose Not attempted, photograph the answer individually or select a result yourself. Confirming keeps full pages and answer regions available for review and clears temporary grading images. Paper codes of the same length tolerate one differing character. For problem pages, “Use these photos and continue grading” reuses locations and the attempt quota. Unreadable pages become missing answers, while mismatched pages keep their located answers. If location fails, “Grading could not start. Try again” offers “Submit again” or “Enter results myself”. Manual entry leaves every question unjudged and keeps full photos available to browse.

### My work

Open `/history` from the first learning row in Me, the review-streak stamp on Today, See today's work after reviewing, See this day after selecting a statistics-calendar cell, or an attempt date in the original question's review summary. The statistics calendar keeps its existing import/activity counts; My work counts valid answers only.

Weeks start on Monday. Hollow circles mean no answers, filled circles mean some answers, and checks mean all answers were correct. Today has a text label. Use arrows to change weeks or the month heading to open the month calendar; future dates cannot be selected. Selecting a day puts it first, followed by older work. Pages use seven-day windows; empty windows follow the API to the nearest older work until no earlier records remain.

The compact week strip places Back to today to the right of the month heading, shown only when another date is selected or the displayed week excludes today. Day summaries and list headings share localized dates. Detail timestamps omit the year; durations below a minute show seconds only, while longer durations show minutes and seconds. Question previews truncate at 120 characters with an ellipsis (…); when the boundary falls inside a formula, the preview stops before that formula.

Choose All or one subject, and optionally Only the near misses. Portrait tablets and phones place these controls under Filter. Dates, records and filters are kept in the URL (`date`, `record`, `subjectId`, `result=wrong`) across refreshes and direct links. Result filtering leaves calendar dots unchanged.

Days group reviews, similar questions, exams and manual entries. Papers start collapsed and can be expanded or opened. Summaries count answers, correct attempts and saved review time; gray Not attempted entries are excluded from answered totals. Select a row to see its question, saved answer, collapsed AI transcription and reference answer, grading reason and confidence. Enlarge figures and answer images; Open original question appears when available. This page is read-only; corrections stay on the original question or paper.

At widths of 1024px or more, the list and details sit side by side. Details stay near the top of the viewport and long content scrolls within the column; without a selected record, the right column shows a text summary by subject. Close clears the selection and returns to the day summary, including while details are loading. Narrower screens open a bottom panel that preserves list position when closed. Notebook, simple and dark styles are supported. Loading uses skeletons, failures offer Retry, and empty days, filters and accounts have separate messages.

### Read-only practice history APIs

These endpoints return the current user's `review`, `practice`, `exam` and `manual` records. Duplicate imports and ungraded records are excluded. `result` takes precedence, with `isCorrect` as a fallback for legacy null results. `not_attempted` remains in lists and is excluded from attempted totals. Dates use the application time zone.

| Endpoint | Parameters and response |
| --- | --- |
| `GET /api/practice/history` | `before=YYYY-MM-DD` is an exclusive upper bound, defaulting to tomorrow; `days=1–31` defaults to 7. Optional `subjectId` and `result=wrong`; `date=YYYY-MM-DD` takes precedence and selects one day. Returns `{ days: [{ date, summary, records }], nextBefore, hasMore }`, with dates descending and records ascending by time. Empty windows jump directly to the window containing the nearest earlier record. A specified empty date stays empty. `nextBefore` is the exclusive upper bound for the next window and is `null` on the final page. |
| `GET /api/practice/history/calendar?from=&to=` | Both dates are inclusive, up to 62 days; supports `subjectId`. Returns `{ days: [{ date, total, correct }] }`, including zero-filled dates. |
| `GET /api/practice/record/:id` | Returns the question, figure, reference answer, explanation, saved response, AI transcription, grading reason, duration and exam link. Missing or other users' records return 404. Review and manual records use the current original question; similar-question and exam records use saved snapshots. Local answer images use `/api/error-items/:id/image?record=&field=answer`. |

`summary` contains `total`, `correct`, `wrong`, `notAttempted` and `reviewDurationSec`, which sums review durations only. The calendar is independent of the wrong-only filter. Invalid dates, ranges and `subjectId` values outside the current user's notebooks return 400. Existing `DELETE /api/practice/record/:id` remains available to the existing correction flow.
