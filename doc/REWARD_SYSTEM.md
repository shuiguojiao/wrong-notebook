# 趣味奖励：能量豆、勇者题与成就章

状态：已确认（2026-11-11），未实现。主力设备为 iPad 横屏，同时兼容手机。用词与风格遵循 `doc/STUDENT_UI.md`，与 `doc/REVIEW_SCHEDULING.md`、`doc/PRACTICE_HISTORY.md` 配合。

## 1. 想解决什么

| 希望小朋友做到 | 现在有什么 | 缺什么 |
| --- | --- | --- |
| 每天都来改错题 | 今天页的任务便签、连续天数红章、收工章 | 来了没有“到手”的奖励；断一天连续数归零，容易灰心 |
| 勇于做难题 | 题目有 1～5 星难度（`difficultyStars`），复习时显示 | 难题和简单题待遇一样，做错还要“明天再见”，没有理由主动碰难题 |
| 坚持下去有盼头 | 收集册按知识点贴纸（全部掌握才贴） | 贴纸周期长，一张要几周；中间没有小目标和小惊喜 |

现有口径只奖励“改正”（`STUDENT_UI.md` 第 6 节）。本设计在此之上增加三件事：**来了就有**（能量豆）、**敢试就有**（勇者题）、**坚持就有**（成就章与周手账）。保留原则：不排名、不比速度、不拿学生互相比较、不让连续天数变成压力。

## 2. 设计原则

1. **奖励行为，不只奖励结果**：敢做难题，做错也给勇气分；做对翻倍。
2. **小额、即时、看得见**：每题几颗豆，当场充进去，收工时合计。
3. **有惊喜但不赌博**：盲盒贴纸只在完成周目标时打开，不花钱、不抽重复、不能靠刷题多开。
4. **允许休息**：连续天数可用“请假卡”补上，断了也不显示红色的 0。
5. **防刷题**：每日有上限，加练与试卷计分有限；重复导入、手动录入结果不计。
6. **得到的不收回**：删题、重标、撤销评估都不扣豆；只有 3 秒撤回会把那一笔抹掉。
7. **不新增比较维度**：没有排行榜、没有“比上周少”，周手账只讲自己的事。

## 3. 三件奖励

### 3.1 能量豆：每天都能攒的点数

为什么不叫“星星”：难度已经用“4 星题”表达，再用星星做点数会混淆。能量豆的意思是“做一题充一点能量”，男孩女孩、小学初中都不别扭，图标一颗豆子，与贴纸、印章分得开。命名只在文案层，改名只改 i18n。

| 行为 | 能量豆 | 每日上限 | 说明 |
| --- | --- | --- | --- |
| 复习一道题（有效作答，对或错） | 1 | 每天 40 | 来了就有；作答记录不区分今日任务与“再来一组”，统一按天封顶 |
| 做对一道上次做错的题（改正） | +2 | — | 对应“这次做对”；错题第一次复习就做对也算改正，之后看最近一条有效作答是否做错 |
| 做勇者题（见 3.2，4～5 星） | +2，做对再 +3 | 每天最多 3 道计分 | 做错同样有 2 颗 |
| 举一反三做一道 | 1，做对 hard / harder 难度为 3 | 每天 5 道 | 加练有少量奖励，不能靠它刷 |
| 在线做卷 / 拍照交卷，每题 | 1 | 每卷 20 | 手动录入结果不计 |
| 一道题彻底掌握 | 5 | — | 取掌握状态由非掌握变为掌握 |
| 贴上一张知识点贴纸 | 20 | — | 收集册现有口径 |
| 完成今日任务（收工章） | 5 | 每天 1 次 | 需全科队列核对，与现在收工章条件一致 |
| 连续天数到 3 / 7 / 14 / 30 / 60 / 100 天 | 10 / 20 / 30 / 50 / 80 / 100 | 每段连续每个里程碑 1 次 | 断掉后重新连续可以再得；用请假卡补上的天也算 |
| 达成周目标 | 30 + 盲盒 1 个 | 每周 1 次 | 见 3.4 |

一天的样子：复习 8 题（8）+ 两道改正（4）+ 一道勇者题做对（5）+ 收工（5）= 22 颗。一周坚持 5 天约 110～150 颗，加上周目标 30。数字不大，是为了让成就章和贴纸显得贵重。

能量豆首版的用处：

- 今天页头部显示余额，收工页逐条“盖”出本次所得。
- 兑换手账装饰：封面花纹、便签颜色、印章样式、头像框（第 7 节 R4，纯 SVG，可分批补）。
- 家长奖励券（可选，默认关闭，见 3.5）。

不做：能量豆换“跳过复习”“少做一题”之类会削弱学习的东西。

### 3.2 勇者题：每天一道敢不敢

目的：给难题一个专门的位置和专门的奖励，把“做错很丢脸”换成“敢做就赢了”。

- 每天从学生自己的题里选 1 道作为“今天的勇者题”，在今天页单独一张卡：难度星、科目、知识点、“敢不敢？”按钮。完全自愿，不做不影响任务完成和连续天数。
- 选题顺序：今日队列中难度最高且 ≥ 4 星的题 → 未掌握、未到期的 ≥ 4 星题（按 `REVIEW_SCHEDULING.md` §7.3 提前复习规则计调度）→ 都没有则不显示卡片，不凑数。首版不用 AI 生成 harder 变式凑题，之后如需再议。
- 同一天选题固定（当天首次打开时决定并记账），刷新不换题；今天的做完后不再给第二道。
- 做的流程就是复习或举一反三原流程，只在作答确认后多一个勇气章：做对“勇者！+5”，做错“勇者也会摔跤 +2，明天再见”。错了走正常调度，没有额外惩罚。
- 不限于勇者题卡：学生在任何入口做 4～5 星题，同样按勇者题计分，每天最多 3 道。卡片只是把它摆到眼前。
- 难度来源：`ErrorItem.difficultyStars`（AI 识别时评定，详情页可改）；举一反三用 `PracticeRecord.difficulty` 的 `hard` / `harder`。没有星级的题按 3 星处理，不算难题。学生自己把题改成 5 星也只多拿几颗豆，不值得作弊，不做防护。

### 3.3 成就章：一次性的印章

和知识点贴纸分开：贴纸讲“学会了什么”，成就章讲“你是怎样坚持的”。首版 16 枚，分四类，其中 3 枚隐藏（得到前只显示“？”）。

| id | 类别 | 名称 | 条件 | 获得日 |
| --- | --- | --- | --- | --- |
| `streak-1` | 坚持 | 第一天 | 历史最长连续 ≥ 1 天 | 第一个完成日 |
| `streak-3` | 坚持 | 一小步 | 历史最长连续 ≥ 3 天 | 第一次连到第 3 天 |
| `streak-7` | 坚持 | 一周 | 历史最长连续 ≥ 7 天 | 第一次连到第 7 天 |
| `streak-14` | 坚持 | 半个月 | 历史最长连续 ≥ 14 天 | 第一次连到第 14 天 |
| `streak-30` | 坚持 | 一个月 | 历史最长连续 ≥ 30 天 | 第一次连到第 30 天 |
| `streak-100` | 坚持 | 一百天 | 历史最长连续 ≥ 100 天 | 第一次连到第 100 天 |
| `brave-1` | 勇气 | 第一次出手 | 第 1 次 ≥ 4 星题的有效 review / exam 作答 | 该记录的应用日 |
| `brave-10` | 勇气 | 十次出手 | 第 10 次勇者作答 | 该记录的应用日 |
| `brave-comeback` | 勇气 | 摔倒再爬起 | 同一道 ≥ 4 星题先 wrong，之后 correct | 那次 correct 的应用日 |
| `sticker-1` | 改正 | 第一张贴纸 | 收集册已贴上 ≥ 1 张 | 最早非回填 sticker 账目的 day，否则结算日并标回填 |
| `notebook-mastered` | 改正 | 整本掌握 | 一个错题本（科目）至少 5 题且全部 mastered | 结算日 |
| `sticker-week-3` | 改正 | 三连贴 | 同一自然周内 3 条非回填 sticker 账目 | 第 3 条的 day |
| `correction-10` | 改正 | 知错就改 | 累计 10 条 correction 账目（回填也算） | 第 10 条的 day |
| `early-bird` | 隐藏 | 早起鸟 | 某天有 done 账目，且该天全部有效 review 作答均在 07:00 前 | 该天 |
| `weekend` | 隐藏 | 周末也在 | 同一周六、日均为完成日 | 周日 |
| `full-week` | 隐藏 | 全勤周 | 同一周一至周日均为完成日 | 周日 |

- 完成日与连续天数沿用 `computeStudentProgress` 和 `stats-streak.ts`；周按应用时区的周一至周日。勇者作答不受每日勇气计分上限影响，手动录入试卷结果不算。
- 每枚只记一次 `type=badge`、`points=0`、`refKey=badge:<id>`，`day` 为获得日，meta 保存规则版本、badgeId、earnedDay 与可选 backfilled。可从历史记录推出的日期写真实日期，不标回填；整本掌握等无历史日期的成果在首次结算时标回填。
- 成就只增不减，删题、撤回、掌握状态回落不收回。近 7 个应用日的新成就不含回填章。
- 不设速度类、名次类成就。
- 获得时在收工页盖章（红章落纸的短动画，不循环），未复习就打开也会在今天页用一条便签告知。
- 成就章放在收集册新页签“成就”，已获得的显示日期，未获得的显示条件（隐藏章除外）。

### 3.4 周目标、周手账与盲盒贴纸

- **周目标**：一周复习天数，学生在“我的”里选 3 / 4 / 5 天，默认 4，给休息留余地。今天页用 7 个小圆点显示本周进度，完成的点变成能量豆。
- **达成**：当周第 N 个完成日的收工页里，多出“本周目标达成！”，+30 能量豆，并开一个盲盒。
- **盲盒贴纸**：趣味贴纸集，与知识点贴纸分开陈列在收集册“趣味贴纸”页签。首版 3 套各 12 张（文具 / 小动物 / 太空），用表情符号或简单 SVG 即可开工，后续可换定制图。每次从未拥有的里面随机抽，集齐一套再给 50 颗豆；三套集齐后盲盒改为随机 30 颗豆，不会“开到重复”。
- **周手账**：每周一（或下周首次打开）在今天页置顶一张可翻过去的纸：这周复习了几天、几道题、改正几道、勇者题几道、新成就、新贴纸、“本周最勇敢的一刻”（取难度最高的一次作答，附题目预览）。只有自己的数据，没有同比环比。周手账可在“我的 → 做题记录”翻看以前的周。
- 周的定义：按应用时区，周一到周日，与 `student-progress.ts` 现有 `weekStart` 一致。

### 3.5 连续天数：请假卡与温和归零

- 每连续 7 天得 1 张请假卡，最多存 2 张；今天页印章旁显示小角标。
- 缺一天时，若有请假卡，下次打开自动补上（记一笔账，显示“用了一张请假卡，连续还在”），学生不用操作；连缺两天只补一天，连续数从补上的那天往后算。
- 没有卡时断掉：印章显示“上次连续 12 天，今天重新开始”，不显示红色 0，不弹窗。
- 其余口径沿用 `STUDENT_UI.md` 6.2：当天有效复习作答即为完成日；录入、跳过、加练不算。

### 3.6 家长奖励券（可选，R4）

家长在“我的 → 奖励设置”里写几张券：“30 分钟动画片 = 60 颗”“周末去游乐园 = 300 颗”。小朋友攒够后点“兑换”，出现“请家长确认”页（4 位家长口令，设置时填），确认后扣豆并记一笔。

- 默认关闭，不配置就不出现任何入口。
- 口令只用于确认兑换，散列存储，不是账户密码。
- 这是外在奖励里最强的一种，容易盖过学习本身的乐趣，所以放最后一期，并在设置页提示“建议配体验类奖励，少配物质奖励”。

## 5. 数据与接口

### 5.1 为什么要记账而不只推算

收集册与连续天数是从作答记录推算的，不新增表。能量豆不能只靠推算：请假卡用掉、盲盒抽到哪张、兑换扣花、当天勇者题选了哪道，都是记录里没有的事实；规则以后调整时，已经给出去的豆也不该变。因此新增一张**只追加**的账本表，推算只用于首次回填。

### 5.2 数据模型（需迁移，备份格式 19 → 20）

```prisma
model RewardEntry {
  id        String   @id @default(cuid())
  userId    String
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  day       String   // 应用日 yyyy-MM-dd
  type      String   // review | correction | brave | practice | exam | mastered | sticker | done | streak | weekly | badge | blindbox | leave_earn | leave_use | redeem | backfill
  points    Int      // 能量豆增减；成就、请假卡、盲盒可为 0
  refKey    String   // 幂等键：如 record:<id>、badge:<name>、streak:<days>、week:<weekStart>、leave:<day>
  meta      String?  // JSON：题目 id、难度、贴纸 key、规则版本等
  createdAt DateTime @default(now())

  @@unique([userId, type, refKey])
  @@index([userId, day])
}
```

`User` 新增：`weeklyGoalDays Int @default(4)`、`rewardsEnabled Boolean @default(true)`、`parentRewards String?`（JSON，R4）、`parentPin String?`（散列，R4）。勇者题当日选题也写入账本（`type=brave_pick`，`points=0`，`refKey=day`），不另建表。

迁移只新增表和列；旧程序遇到新表不受影响。

### 5.3 记账时机

- 作答保存的同一写入队列里（`db-write-queue`），保存 `PracticeRecord` 后立即调用 `awardForRecord(record)`，按规则写 0～3 条账（review/practice/exam、correction、brave）。幂等键为 `record:<id>`，重复保存不重复记。
- 3 秒撤回（`/api/review/undo`）删除该 record 对应的所有账目。
- 收工、掌握、贴纸、里程碑、周目标、成就：由“结算”完成。`GET /api/rewards/summary` 与 `ledger` 每次先在一个串行事务里重放全部作答记录与派生状态，把缺少的账目补上（R1 实现为 `src/lib/rewards/service.ts` 的 `settleRewards`）；幂等键保证打开多次只记一次。连续里程碑的幂等键带本段连续的起始日。
- 请假卡：计算连续天数时若发现昨天缺席且有可用卡，写 `leave_use`，之后连续天数把该日视为完成日。
- 删题、删作答记录（非撤回）、重标标签：账本不动。

### 5.4 首次回填

用户首次打开今天页时，若无任何账目，用现有作答记录按同一规则回填 review / correction / brave / mastered / sticker / streak 类账目（`meta.backfilled=true`，`day` 取记录当日）；成就章按历史判定并盖上历史日期。不回填收工、周目标、盲盒、请假卡。回填是幂等的，中途失败下次继续。回填出来的掌握、贴纸、连续类账目记在结算当天，但只计入余额，不算作“今天 / 本周所得”，做题记录里也不显示，避免上线第一天凭空多出几百颗。

### 5.5 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/rewards/summary` | 余额、今天所得、本周进度与目标、连续与请假卡、未读成就 / 贴纸、今日勇者题（R1 已有余额、今天、本周、连续、开关） |
| `POST /api/rewards/brave/pick` | 决定并记录今日勇者题（summary 首次调用时内部触发，也可显式调） |
| `GET /api/rewards/week?start=YYYY-MM-DD` | 周手账数据 |
| `GET /api/rewards/badges`、`GET /api/rewards/stickers` | 收集册两个新页签 |
| `GET /api/rewards/ledger?day=` | 做题记录每天的能量豆明细 |
| `PATCH /api/user` | 新增 `weeklyGoalDays`、`rewardsEnabled` |
| `POST /api/rewards/redeem`（R4） | 兑换家长奖励券，需家长口令 |

收工与复习保存接口的响应追加 `rewards` 字段（本次所得明细、新成就、盲盒结果），前端无需再请求一次。

### 5.6 导入导出

`RewardEntry` 按用户整表导出；导入按 `id` 合并，冲突以已有为准；`refKey` 引用的 record 不存在时仍导入（豆是豆，题可以没了）。`User` 新字段随偏好导出。同步 `format.ts`、`export`、`import`、`data-backup.test.ts`。
